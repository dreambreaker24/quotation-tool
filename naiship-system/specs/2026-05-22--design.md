## 功能 1：客戶跟進加入行事曆

### 需求
客戶有「下次跟進」日期（`followUpDate` 字串 YYYY-MM-DD）。使用者可手動將跟進提醒加入行事曆，方便在行事曆頁統一查看。

### 設計
- **`ClientDetail.vue`**：在「下次跟進」欄旁（僅 `client.followUpDate` 有值時）加「＋加入行事曆」按鈕（xs 尺寸，金色邊框）
- 點擊後呼叫 `calendarEventsStore.addEvent()`，payload：
  ```js
  {
    companyId: client.companyId,
    type: 'followup',           // 新事件類型
    date: Timestamp.fromDate(new Date(client.followUpDate)),
    label: `跟進：${client.name}`,
    createdBy: authStore.user?.uid ?? ''
  }
  ```
- **`CalendarTab.vue`**：
  - `eventTypes` 陣列新增 `{ key: 'followup', label: '客戶跟進', color: '#a855f7' }`（紫色）
  - 圖例列加「客戶跟進」紫色標記
  - 行事曆格子的事件渲染加 `event.type === 'followup'` 的紫色背景判斷

### 資料格式
不需新建 Firestore collection，沿用現有 `calendarEvents` collection。

## 功能 2：里程碑 6 期批次模板

### 需求
新案件建立後需要手動逐筆新增收款期款，操作繁瑣。提供一次填寫 6 期模板的快速入口。

### 設計
- **`PaymentMilestones.vue`**：
  - 標題列右側（「+ 新增期款」左邊）加「套用模板」按鈕，當 `milestones.length >= 6` 時隱藏
  - 點擊開啟 Modal，包含 6 行固定表格：

  | 期數名稱（固定） | 金額（必填，0 表示略過） | 到期日（選填） |
  |----------------|----------------------|-------------|
  | 訂金（簽約款）  | input[number]        | input[date] |
  | 第二期款        | input[number]        | input[date] |
  | 第三期款        | input[number]        | input[date] |
  | 第四期款        | input[number]        | input[date] |
  | 第五期款        | input[number]        | input[date] |
  | 尾款            | input[number]        | input[date] |

- 送出規則：金額 > 0 的行才加入，已有的里程碑不覆蓋（append）
- 模板初始值：金額全為 0，到期日全空

## 功能 3：案件刪除（二次確認）

### 需求
目前案件無法刪除，測試資料或誤建案件無法清除。

### 設計

**`stores/cases.js`** 新增：
```js
import { deleteDoc, getDocs, collection } from 'firebase/firestore'

async function deleteCase(id) {
    // 刪除 tasks 子集合
    const taskSnap = await getDocs(collection(db, 'cases', id, 'tasks'))
    await Promise.all(taskSnap.docs.map(d => deleteDoc(d.ref)))
    // 刪除主文件（workTypes、paymentMilestones 為嵌入陣列，隨主文件刪除）
    await deleteDoc(doc(db, 'cases', id))
}
```

> 注意：photos 子集合的 Cloud Storage 檔案不在此次刪除範圍，只清除 Firestore 記錄。

**`CaseEditModal.vue`**：
- 底部左側加「刪除此案件」紅色文字按鈕
- 點擊後切換為行內確認區塊：`"⚠ 確定刪除「{案件名稱}」？此操作無法復原"` + 「確認刪除」紅色按鈕 + 「取消」
- 確認後執行 `casesStore.deleteCase(caseId)` → 關閉 Modal → `emit('close')`
- 刪除中顯示 loading 狀態，防止重複點擊

## 功能 4：工種付款進度顯示

### 需求
WorkTypePanel 顯示每個工種的廠商費用，但看不出已付了多少。

### 設計
- **`WorkTypePanel.vue`**：每個工種列，廠商費用旁加「已付 $X」小標記
- 計算：`wt.vendorPayments?.reduce((s, p) => s + (p.amount || 0), 0) ?? 0`
- 顏色規則：
  - 已付 = 0 或未設定：灰色
  - 0 < 已付 < 總費用：橘色
  - 已付 ≥ 總費用（且 > 0）：綠色

## 功能 5：Gantt 狀態篩選 chip

### 需求
案件數量多時，想只看特定狀態（如施工中＋待結算）。

### 設計
- **`GanttTab.vue`**：表格上方加一排 chip，共 7 個狀態
- 資料：`const activeStatuses = ref(new Set(Object.keys(STATUS_BAR_COLORS)))`（預設全選）
- chip 樣式：選中時用對應 STATUS_BAR_COLORS 填色，未選時灰底
- `regionCases` computed 加入篩選：`.filter(c => activeStatuses.value.has(c.status))`
- chip 點擊：toggle 對應 status 的 Set 成員
- 狀態不持久化（每次進頁面重置為全選）

## 功能 6：工作日誌週報匯出 Excel

### 需求
週檢視包含多員工的工作記錄，需要匯出供管理或存檔。

### 設計
- **`WorkJournalTab.vue`**：週檢視模式下，頂部右側加「匯出本週」按鈕
- 匯出欄位：

  | 員工姓名 | 日期 | 案件回報 | 其他工作 | 油資(km) | 油資($) |
  |---------|------|---------|---------|---------|--------|

  - 案件回報：`log.caseEntries` 合併為「案件名: 內容\n案件名: 內容」字串（舊格式 `log.content` 直接帶入）
  - 其他工作：`log.otherItems` 合併為換行字串
  - 油資公里數：`log.fuelExpenses` 各筆 distance 加總（相容舊格式 `log.fuelExpense.distance`）
  - 油資金額：km × 6

- 油資金額 = km × 6（沿用現有計算）
- 使用現有 `xlsx` 套件（已安裝）
- 檔名：`工作日誌_YYYY-MM-DD_YYYY-MM-DD.xlsx`（週起迄）
- 若當週無資料，`alert('本週無日誌記錄')` 並不下載
