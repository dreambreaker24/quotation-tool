# 行事曆農曆國字顯示 — 設計文件

## 背景

奈拾行事曆（`src/components/cases/CalendarTab.vue`）先前已完成一輪視覺改版（配色、事件色塊高度／圓角統一），已部署上線。這份 spec 處理視覺改版時特意延後的「真功能」之一：在每個日期數字旁顯示農曆國字，比照人事行政總處官方辦公日曆表的呈現方式。

另一項延後功能（請假事件跨天合併長條顯示）風險與複雜度較高（牽動拖曳、點擊編輯、當天詳情視窗等現有互動邏輯），拆成獨立的一輪 spec，不在本文件範圍內。

## 目標

- 行事曆每一格（含上月／下月溢出格）日期數字旁顯示對應的農曆國字
- 顯示規則跟官方日曆表一致：
  - 當天是 24 節氣之一 → 顯示節氣名稱（如「寒露」「霜降」）
  - 當天是農曆初一 → 顯示農曆月份名（如「九月」）
  - 其他日子 → 顯示農曆日期國字（初一～三十、廿九等）
- 換算必須能算任何年份／月份（使用者翻月份瀏覽時都要對），不能像先前的設計稿一樣手動查表寫死單一個月
- 當天若同時是國定假日，假日名稱跟農曆用「・」接在同一行顯示（如「25 十六・中秋節」），取代目前單獨一行的假日名稱顯示

## 不在範圍內

- 請假事件跨天合併長條顯示（另立 spec）
- 農曆年份（干支紀年）、生肖等其他農曆延伸資訊
- 除了 CalendarTab.vue 之外的其他頁面串接農曆顯示

## 架構

### 新增檔案：`src/utils/lunarCalendar.js`

獨立、零外部依賴的純函式模組，整理公開的「1900–2100 年農曆對照演算法」（廣泛用於農民曆網站，來源成熟、資料範圍涵蓋遠超過本系統實際會用到的年份）與 24 節氣計算。

對外只開一個函式：

```js
/**
 * @param {Date} date 西曆日期
 * @returns {string} 當天要顯示的農曆文字（節氣名 / 農曆月份名 / 農曆日期國字）
 */
export function getLunarLabel(date) { ... }
```

此函式為純計算、同步、不會失敗（輸入範圍 1900–2100 內任何日期皆有效），不需要 loading 或錯誤狀態處理。1900–2100 之外的日期（理論上使用者不太可能翻到）回傳空字串，呼叫端不顯示。

模組內部保留（不對外開放）的資料表與計算函式：
- 農曆年資料表（各年份閏月位置、大小月分布，1900–2100）
- 農曆日期 ↔ 西曆日期的雙向換算
- 24 節氣的西曆日期計算（天文近似公式）
- 農曆數字 → 國字對照（初一～三十、正月～臘月、廿一～廿九等）

### CalendarTab.vue 改動

1. `calendarCells` computed：三個組 cell 的地方（上月溢出、當月、下月溢出）都加一個欄位：
   ```js
   lunarLabel: getLunarLabel(date)
   ```
2. 樣板：原本分開的日期數字 `<span>` 與假日名稱 `<div>` 合併成同一行：
   ```html
   <div class="flex items-center gap-2">
     <span ...日期數字樣式.../>{{ cell.day }}</span>
     <span class="text-[10px]" :style="...">
       {{ cell.holidayName ? `${cell.lunarLabel}・${cell.holidayName}` : cell.lunarLabel }}
     </span>
   </div>
   ```
   顏色沿用目前已上線的規則：`cell.isNonWorking` 時用 `#A34848`，其餘用中性灰階。
3. 移除原本獨立一行的 `cell.holidayName` 顯示區塊（被步驟 2 取代）。

### 資料流

```
calendarCells (computed)
  └─ 每個 cell 呼叫 getLunarLabel(date) → 純計算，同步回傳字串
       └─ 樣板讀 cell.lunarLabel / cell.holidayName 組字串顯示
```

不涉及 Firestore 讀寫、不影響現有的事件資料模型、不影響拖曳／點擊／新增／編輯等互動邏輯。

## 錯誤處理

- 換算函式輸入範圍外（理論上不會發生，calendarCells 只會產生近三個月內的日期）回傳空字串，樣板端 `cell.lunarLabel` 為空字串時不會多顯示任何符號
- 沒有額外的使用者可見錯誤情境（純顯示、無網路請求、無使用者輸入）

## 測試計畫

1. **新增 `tests/utils/lunarCalendar.test.js`**：用幾組可公開查證的日期核對換算結果，至少涵蓋：
   - 一般農曆日期（如 2026-10-11 → 農曆初二）
   - 農曆月初一（如 2026-10-10 → 顯示「九月」而非「初一」）
   - 節氣當天（如 2026-10-08 寒露、2026-10-23 霜降）
   - 跨農曆年（如農曆新年前後）
   - 閏月年份的月份判斷（挑一個已知有閏月的年份核對）
2. **`tests/components/CalendarTab.test.js`**：既有 53 項測試需全數維持通過；假日名稱顯示位置改變（從獨立一行改成跟農曆同一行、用「・」接），如果有測試斷言舊的顯示位置／格式，需要同步調整斷言內容，不能刪測試來讓它過
3. **視覺驗證**：比照先前視覺改版的作法，用 Playwright 對本機開發伺服器實際截圖，核對幾個關鍵日期（一般日、農曆初一、節氣、國定假日）的顯示文字是否正確且排版沒有跑版，之後才部署到正式站
